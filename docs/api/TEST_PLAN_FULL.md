# 全面项目测试计划 - CampusTutor

本项目包含四个主要部分：Java 后端、微信小程序（移动端）、Web 门户（Web 端）、后台管理系统（Admin）。测试将分为 **单元/接口测试**、**功能测试**、**端到端流程测试** 和 **非功能测试**。

## 1. 后端服务测试 (campus-backend)

**核心目标**：确保数据逻辑正确、API 稳定、数据库交互无误。

### 1.1 基础模块
- [ ] **认证鉴权 (Auth)**:
    - 注册（手机号/邮箱/验证码）、登录（密码/验证码）、登出。
    - Token 有效性检查、Token 过期刷新。
    - 权限拦截（未登录访问受限接口）。
- [ ] **用户管理 (User)**:
    - 用户信息更新（头像、昵称）。
    - 角色切换（如果有）。

### 1.2 核心业务模块
- [ ] **家教需求（Parent/Demand）**:
    - 发布需求（参数校验：科目、年级、价格范围、地址）。
    - 修改/关闭需求。
    - 查询需求列表（筛选、分页）。
- [ ] **教师认证与管理 (Tutor)**:
    - 提交认证资料（OCR 识别测试、文件上传）。
    - 修改个人简历/履历。
    - 设置教学科目与时间。
- [ ] **匹配系统 (Match)**:
    - 算法测试：发布需求后，是否正确推荐符合条件的老师。
    - 老师主动报名需求逻辑。
- [ ] **订单与支付 (Order/Wallet)**:
    - 创建订单、订单状态流转（待支付 -> 进行中 -> 已完成 -> 已退款）。
    - 钱包充值、提现、余额扣减逻辑（并发安全）。
    - 支付回调模拟测试。
- [ ] **教学管理 (Teaching)**:
    - 课程表生成。
    - 课时记录、打卡逻辑。
- [ ] **地图服务 (Map)**:
    - 经纬度存储与计算。
    - 搜索“附近的老师/学生”接口准确性（Redis Geo 或 数据库查询）。
- [ ] **AI 服务 (LLM/OCR)**:
    - LLM 对话接口响应时间与内容质量。
    - OCR 图片上传识别成功率。

### 1.3 自动化测试执行
建议运行现有的 Maven 测试套件：
```bash
cd campus-backend
mvn test
```
*关注 `surefire-reports` 目录下的测试报告。*

## 2. 微信小程序测试 (user-app)

**核心目标**：移动端用户体验、硬件调用（定位/相机）、微信生态集成。

### 2.1 公共功能
- [ ] **启动与授权**: 微信一键登录、获取用户信息授权、地理位置授权。
- [ ] **导航栏**: 底部 Tab 切换流畅性（首页、消息、我的）。

### 2.2 家长端 (Parent Role)
- [ ] **找老师**:
    - 筛选老师（地图模式 vs 列表模式）。
    - 查看老师详情（简历、评价）。
- [ ] **需求管理**:
    - “发布需求”流程体验（Step 1-3 表单填写）。
    - 查看 “我的需求” 及应聘老师。
- [ ] **错题本 (WrongBook)**:
    - 拍照上传错题（调用相机/相册）。
    - 错题列表展示与详情查看。

### 2.3 教师端 (Teacher Role)
- [ ] **入驻认证**:
    - 身份证/学历证书上传与预览。
    - 实名认证状态反馈（审核中/通过/拒绝）。
- [ ] **接单广场**:
    - “地图找生源”功能（地图撒点是否准确、点击气泡展示详情）。
    - 申请接单操作。
- [ ] **课程管理**:
    - 课表视图（日历展示）。
    - 课程打卡签到（可能涉及定位校验）。

## 3. Web 门户测试 (campus-web)

**核心目标**：PC 端大屏体验、响应式适配、通过浏览器访问的主要入口。

### 3.1 界面适配
- [ ] **响应式测试**: 在 1920x1080, 1366x768 以及 手机H5 模式下布局是否正常。
- [ ] **兼容性**: Chrome, Edge, Firefox, Safari 下的表现。

### 3.2 功能模块
- [ ] **AI 助手 (Service/AiChat)**:
    - 聊天窗口的发送与流式响应显示。
    - 历史记录加载。
- [ ] **个人中心 (Mine)**:
    - 订单列表渲染（Web 端通常展示更多列信息）。
    - 钱包页面（充值/提现表单）。
- [ ] **流程一致性**:
    - 在 Web 端发布的需求，在小程序端是否同步可见。
    - 在 Web 端发起的聊天，小程序端是否收到通知。

## 4. 后台管理系统测试 (web-admin)

**核心目标**：数据管理、审核流程、系统配置。

### 4.1 审核测试
- [ ] **教师审核**:
    - 模拟小程序端提交认证 -> 后台列表显示 -> 管理员点击通过/驳回 -> 小程序端状态变更。
- [ ] **需求/内容审核**:
    - 敏感词过滤、违规需求下架。

### 4.2 数据管理
- [ ] **用户列表**: 封禁/解封用户、重置密码。
- [ ] **订单列表**: 查看所有订单状态、处理纠纷（强行退款/结束订单）。
- [ ] **财务对账**: 钱包流水记录查询。

### 4.3 基础功能
- [ ] **仪表盘 (Dashboard)**: 数据统计图表是否正确加载。
- [ ] **字典/配置**: 修改系统参数后是否即时生效。

## 5. 端到端场景测试 (E2E Scenarios)

**核心目标**：串联多端，模拟真实业务闭环。

### 场景一：完整的家教聘用流程
1. **家长 (Web/App)**: 注册并发布一条“初二数学”的找老师需求。
2. **教师 (App)**: 在“接单广场”看到该需求，并发起应聘/沟通。
3. **家长 (App)**: 收到应聘通知，查看老师简历，点击“确认聘用”并支付/预定。
4. **系统**: 生成订单，状态变为“进行中”。
5. **教师 (App)**: 查看课表，可以进行课时签到。
6. **家长 (App)**: 确认已上课。
7. **系统**: 资金从托管账户划转至教师钱包。

### 场景二：教师认证闭环
1. **教师 (Web/App)**: 提交认证资料。
2. **管理员 (Admin)**: 在后台审核页面看到待办，点击“通过”。
3. **教师 (Web/App)**: 收到通知，身份变为“认证教师”，解锁接单权限。

## 6. 性能与安全测试

- [ ] **并发测试**: 模拟 50-100 人同时抢单/搜索（JMeter/K6）。
- [ ] **安全测试**:
    - SQL 注入扫描（针对搜索框）。
    - 越权访问（普通用户尝试访问 Admin 接口）。
    - 文件上传漏洞（上传非图片文件是否被拦截）。
