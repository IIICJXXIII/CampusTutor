## 二、项目背景与目标

### 2.1 项目背景

随着素质教育市场的快速发展，家长寻找合适的家教老师面临以下问题：
- 信息不对称：难以获取教员的真实资质和教学能力
- 匹配效率低：传统方式依赖人工筛选，效率低下
- 缺乏智能推荐：无法根据学生情况精准匹配合适的教员
- 交易无保障：缺乏资金托管和教学过程监管

### 2.2 项目目标

- 解决家教服务领域供需匹配难题
- 通过智能算法精准连接优质教育资源与需求方
- 构建高效、透明、可靠的家教服务生态系统
- 实现从需求发布到服务评价的完整闭环

## 六、核心业务流程

### 6.1 需求发布与接单流程

```
家长发布需求 → 系统智能匹配 → 教员查看/申请 → 家长确认 
     → 创建订单 → 支付 → 上课 → 完课 → 评价
```

### 6.2 订单状态流转

| 状态码 | 状态名 | 描述 |
|--------|--------|------|
| 0 | 待支付 | 订单已创建，等待家长支付 |
| 1 | 已支付待上课 | 支付完成，等待开课 |
| 2 | 进行中 | 正在上课中 |
| 3 | 已完成 | 课程完成，已结算 |
| 4 | 已取消 | 订单取消 |
| 5 | 退款中 | 申请退款中 |
| 6 | 已退款 | 退款完成 |

### 6.3 教员认证流程

```
提交资料 → 待审核 → 审核通过/拒绝 → 认证完成
```

认证状态：0-待提交, 1-待审核, 2-已通过, 3-已拒绝

### 7.2 匹配评分维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 科目匹配 | 30% | 教员可授科目与需求科目匹配 |
| 年级匹配 | 20% | 教员可授年级与需求年级匹配 |
| 距离因素 | 15% | 基于LBS的距离计算 |
| 价格匹配 | 10% | 期望价格区间匹配 |

| 等级 | 名称 | 曝光量 | 晋升条件 |
|------|------|--------|----------|

| HOT | 热门池 | 高曝光 | 评分≥4.5且订单数≥10 |

### 8.2 RAG检索增强系统

平台已实现基于RAG（检索增强生成）的知识库问答系统，提升AI对话的专业性和准确性。

**系统架构：**

```
┌─────────────────────────────────────────────────────────┐
│                    RAG系统架构                           │
├─────────────────────────────────────────────────────────┤
│  用户提问 → 关键词提取 → 知识库检索 → 上下文注入 → LLM回答  │
└─────────────────────────────────────────────────────────┘
```

**知识库管理接口：**

| 接口 | 方法 | 说明 |
|------|------|------|
| /api/knowledge/list | GET | 分页查询知识库 |
| /api/knowledge/{id} | GET | 获取文档详情 |
| /api/knowledge | POST | 创建知识文档 |
| /api/knowledge/{id} | PUT | 更新知识文档 |
| /api/knowledge/{id} | DELETE | 删除知识文档 |
| /api/knowledge/search | GET | 搜索知识库 |

**知识库内容分类：**

| 类型 | 数量 | 说明 |
|------|------|------|
| LESSON_PLAN | 3 | 教案模板 |
| TEACHING_EXPERIENCE | 3 | 教学经验 |
| FAQ | 3 | 常见问题 |
| RULE | 2 | 平台规则 |
| POLICY | 1 | 政策说明 |

**核心实现文件：**

| 文件 | 说明 |
|------|------|
| KnowledgeDocument.java | 知识文档实体类 |
| KnowledgeDocumentMapper.java | 数据访问层 |
| KnowledgeRetrievalService.java | 检索服务（关键词提取+文档匹配） |
| KnowledgeDocumentService.java | 文档管理服务 |
| KnowledgeController.java | REST API控制器 |

### 8.3 AI应用场景示例

**场景1：需求智能解析**
- 用户输入："我想找一个会弹钢琴的老师，孩子上小学三年级"
- 系统解析：科目=钢琴, 年级=小学三年级

**场景2：教案自动生成**
- 输入：学生年级、科目、基础水平、学习目标
- 输出：包含教学目标、教学重点、课时安排的完整教案

**场景3：评语专业润色**
- 输入："学生表现不错，有进步"
- 输出："该生学习态度端正，课堂表现积极，在知识点掌握上有明显进步，建议继续保持"

## 十一、项目创新与特色

### 11.1 技术创新

1. **DeepFM深度学习匹配**（已实现）
   - 采用深度因子分解机模型实现精准推荐
   - 结合ONNX推理引擎实现高效预测
   - 模型文件：`campus_deepfm.onnx`，已集成到后端服务
   - 具备降级策略：当模型推理异常时，自动切换到规则评分

2. **多级推荐架构**（部分实现）
   - ✅ 规则打分：已实现（科目、年级、距离、价格等维度）
   - ✅ 协同过滤：已实现（`CollaborativeFilteringServiceImpl`）
   - ✅ DeepFM精排：已实现（`DeepFMInferenceService`）
   - ⏳ 实时意图：规划中（Redis Stream方案已设计）
   - ⏳ 流量池赛马：规划中（BASIC/WARM/HOT三级曝光机制）

3. **AI赋能全流程**（已实现）
   - 从需求解析到教案生成，AI深度参与教学服务全流程
   - 基于DeepSeek API实现高质量对话和内容生成
   - AI功能：智能对话、需求解析、教案生成、评语润色

4. **RAG检索增强系统**（规划中）
   - ⏳ 向量数据库（Milvus）：仅有实施方案文档，无代码实现
   - ⏳ Sentence-BERT向量化：无实现代码
   - ⏳ 知识库表结构：SQL脚本已定义（knowledge_document等），但无Java实体类和服务
   - ⏳ Prompt模板：SQL脚本已定义，但无Java服务实现

### 11.2 业务创新

1. **资金托管机制**（已实现）
   - 家长支付的资金由平台托管
   - 课时完成后才结算给教员
   - 保障双方权益，降低交易风险

2. **LBS地理位置服务**（已实现）
   - 基于Redis GEO的附近需求/教员推荐
   - 支持上门授课场景的距离计算
   - 实时位置打卡确保教学真实性

3. **课时打卡系统**（已实现）
   - GPS定位 + 水印照片双重验证
   - 确保教学过程真实可追溯
   - 支持家长远程确认课时

- 核心代码：`LlmClientService.java`
