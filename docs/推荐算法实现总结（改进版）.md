# CampusTutor 推荐算法实现总结

> 基于 Spring Boot 3 + Redis 的轻量级实时推荐系统，涵盖多维加权评分、协同过滤、实时意图追踪、流量池赛马四大核心模块。

---

## 1. 系统架构总览

```
家长发起搜索请求
       │
       ▼
┌──────────────────────────────────────────────────────────┐
│                   MatchService (精排引擎)                  │
│                                                          │
│  ① LBS空间召回 ──→ ② 硬性标签过滤 ──→ ③ 多维加权评分        │
│                                         │                │
│                          ┌──────────────┼────────────┐   │
│                          ▼              ▼            ▼   │
│                    ④ 协同过滤      ⑤ 实时意图      ⑥ 流量池 │
│                      混合评分        加分           赛马加分 │
│                          │              │            │   │
│                          └──────────────┼────────────┘   │
│                                         ▼                │
│                              ⑦ 按最终得分降序排列          │
└──────────────────────────────────────────────────────────┘
       │
       ▼
  返回教员列表 + 匹配标签
```

### 核心技术栈

| 组件 | 技术 | 用途 |
|------|------|------|
| 应用框架 | Spring Boot 3.2.1 | 服务骨架 |
| 内存数据库 | Redis 7 | GEO召回、ZSET意图追踪、Streams异步管道、缓存 |
| 关系数据库 | MySQL 8 | 教员/行为/订单持久化 |
| ORM | MyBatis-Plus 3.5.5 | 数据查询 |

## 2. 第一层：LBS 空间召回 + 硬性标签过滤

**目标**：从全库教员中以极低延迟筛出满足基本条件的候选集。

### 2.1 GEO 空间召回

- 所有教员经纬度存储在 Redis GEO 结构中
- 使用 `GEOSEARCH` 以家长坐标为圆心、指定半径（默认 10km）召回附近教员

```java
// GeoService.searchNearbyTutorsWithDistance()
Map<Long, Double> nearbyWithDistance = geoService.searchNearbyTutorsWithDistance(lng, lat, radius);
```

### 2.2 硬性条件过滤

在 MySQL 层面通过 `LambdaQueryWrapper` 执行：

| 过滤条件 | 字段 | 逻辑 |
|---------|------|------|
| 认证状态 | `cert_status = 2` | 只查已认证教员 |
| 科目匹配 | `teach_subjects LIKE '%数学%'` | 模糊匹配 JSON 数组 |
| 年级匹配 | `teach_grades LIKE '%高一%' OR LIKE '%高中全科%'` | 智能年级匹配 |
| 授课方式 | `teach_mode = 1/2/3` | 线上/线下/都可 |
| 价格区间 | `expect_price <= maxPrice` | 预算上限过滤 |

## 3. 第二层：多维加权评分引擎

**核心类**：`MatchScoreCalculator`

### 3.1 评分维度与权重

支持**家长视角**（找老师）和**教师视角**（找需求）双视角独立权重，全部通过 `application.properties` 配置。

#### 家长视角权重（campus.match.parent.*）

| 维度 | 配置键 | 默认值 | 评分逻辑 |
|------|--------|--------|---------|
| 科目匹配 | `parent-subject` | 30.0 | 完全匹配100, 包含80, 不匹配20 |
| 年级匹配 | `parent-grade` | 20.0 | 精确匹配100, 区间重叠80, 无关20 |
| 距离 | `parent-distance` | 15.0 | 0-3km:100, 3-5km:80, 5-10km:60, 线性衰减 |
| 价格 | `parent-price` | 12.0 | 在预算内100, 超出越多衰减越大 |
| 评分 | `parent-rating` | 10.0 | 评分/5 × 100 |
| 教龄 | `parent-experience` | 5.0 | 年限越长分越高 |
| 学历 | `parent-education` | 5.0 | 博士>硕士>本科 阶梯评分 |
| 专业匹配 | `parent-specialty` | 3.0 | 查询科目是否属于教员专业方向 |

### 3.2 评分公式

```
BaseScore = Σ (维度得分_i × 维度权重_i) / Σ 维度权重_i × 100
```

结果归一化到 **0-100 分**。

### 3.3 动态权重调整

**核心类**：`DynamicWeightCalculator`

根据用户的历史搜索行为自动调整各维度权重：
- **新用户**（搜索次数 < 5）：使用默认权重
- **活跃用户**：根据点击偏好自动放大/缩小特定维度权重（如反复点击高价教员 → 降低价格权重）

## 4. 第三层：协同过滤 (CF) 混合评分

**核心类**：`CollaborativeFilteringServiceImpl`

### 4.1 算法原理

采用 **User-Based CF**：
1. 构建用户-教员交互矩阵（基于 `user_action_log` 表）
2. 计算用户间的余弦相似度
3. 为目标用户预测其未交互过的教员的喜好度

### 4.2 混合公式

```
HybridScore = (1 - cfWeight) × ContentScore + cfWeight × CFScore
```

### 4.3 配置参数（campus.cf.*）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `cf-weight` | 0.3 | CF 在混合模型中的权重 |
| `min-common-items` | 2 | 用户间最少共同交互教员数 |
| `top-k-similar-users` | 20 | 选取最相似的 K 个用户 |
| `min-similarity` | 0.1 | 最小相似度阈值 |
| `cold-start-threshold` | 5 | 冷启动行为数阈值 |
| `cache-expire-seconds` | 3600 | 相似度缓存 TTL |

### 4.4 推荐标签

| CF 分数 | 标签 |
|---------|------|
| ≥ 0.7 | "相似家长推荐" |
| ≥ 0.5 | "猜你喜欢" |

## 5. 第四层：实时意图追踪

**核心类**：`RealtimeIntentService` + `IntentEventProducer` + `IntentStreamConsumer`

### 5.1 机制概述

家长浏览教员时，系统实时提取教员身上的核心标签（科目、大学、价格带等），使用 Redis ZSET 原子操作累加到家长专属的意图画像中。搜索时读取 Top-K 标签进行加分。

### 5.2 异步事件流（Redis Streams）

```
BehaviorServiceImpl.recordAction()
       │
       ▼ XADD
Redis Stream "intent:actions"
       │
       ▼ XREADGROUP (auto-ACK)
IntentStreamConsumer.onMessage()
       │
       ▼
RealtimeIntentService.handleUserAction()
       │
       ▼ ZINCRBY
Redis ZSET "realtime_intent:parent:{userId}"
```

**关键组件**：

| 组件 | 职责 |
|------|------|
| `IntentEventProducer` | 使用 `StringRedisTemplate.opsForStream().add()` 发布事件 |
| `IntentStreamConsumer` | 实现 `StreamListener`，消费事件并调用 `handleUserAction()` |
| `IntentStreamConfig` | 配置 `StreamMessageListenerContainer`，自动创建消费者组 |

### 5.3 行为权重表（campus.intent.*）

| 行为 | 配置键 | 默认权重 | 漏斗含义 |
|------|--------|---------|---------|
| 查看详情 | `weight-view` | +1.0 | 浅层兴趣 |
| 收藏教员 | `weight-favorite` | +3.0 | 中度意向 |
| 发送私信 | `weight-chat` | +5.0 | 转化意图 |
| 下单 | `weight-order` | +8.0 | 完成交易 |

### 5.4 教员标签提取规则

`RealtimeIntentService.buildTutorTags()` 从教员 Profile 中提取以下标签：

```
科目标签: "科目:数学", "科目:物理"
大学标签: "大学:北京大学"
学历标签: "学历:硕士在读"
价格标签: "价格:100-150"（按价格带分箱）
授课标签: "授课:线下"
```

### 5.5 意图加分公式

```
IntentBoost = min(maxIntentBoost, β × Σ matchedTagScore_i)
FinalScore = BaseScore + IntentBoost
```

| 参数 | 配置键 | 默认值 |
|------|--------|--------|
| β（放大因子） | `beta-factor` | 1.5 |
| 最大加分上限 | `max-intent-boost` | 15.0 |
| Top-K 标签数 | `top-k-tags` | 5 |
| 半衰期 | `half-life-minutes` | 5 min |
| Session TTL | `session-ttl-minutes` | 30 min |

### 5.6 推荐标签

命中意图标签时展示 **"系统推荐"**。

## 6. 第五层：流量池赛马机制

**核心类**：`TrafficPoolService`

### 6.1 三级流量池

| 级别 | 推荐标签 | 加分 | 晋级条件 |
|------|---------|------|---------|
| **BASIC**（探索期） | "新晋教员" | +5.0 | 默认（新教员保护） |
| **WARM**（验证期） | — | +3.0 | 订单数 ≥ 3 或 观察期后有互动 |
| **HOT**（爆发期） | "明星教员⭐" | +8.0 | 订单数 ≥ 10 且 评分 ≥ 4.5 |

### 6.2 评估逻辑

```java
if (orderCount >= 10 && rating >= 4.5)  → HOT
else if (orderCount >= 3)                → WARM
else if (超过观察期 && 有聊天记录)         → WARM
else                                     → BASIC
```

### 6.3 配置参数（campus.traffic-pool.*）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `basic-boost` | 5.0 | BASIC 池加分 |
| `warm-boost` | 3.0 | WARM 池加分 |
| `hot-boost` | 8.0 | HOT 池加分 |
| `basic-period-days` | 7 | 基础观察期（天） |
| `cache-expire-seconds` | 604800 | 级别缓存 TTL（7天） |

## 7. 最终评分合成

在 `MatchService.searchTutors()` 中，各层得分按以下顺序叠加：

```
① 多维加权基础分                           → 0-100
② + CF 混合评分（if 启用且有数据）           → 调整到 0-100
③ + 实时意图加分（max 15.0）               → 可能超 100
④ + 流量池加分（BASIC+5/WARM+3/HOT+8）    → 可能超 100
⑤ cap at 100.0                           → 最终分数
```

**匹配标签汇总**：

| 标签 | 触发条件 | 来源 |
|------|---------|------|
| "科目匹配" | 科目完全一致 | 基础评分 |
| "年级匹配" | 年级区间重叠 | 基础评分 |
| "距离最近" | 距离 < 3km | 基础评分 |
| "价格合适" | 在预算范围内 | 基础评分 |
| "相似家长推荐" | CF 分 ≥ 0.7 | 协同过滤 |
| "猜你喜欢" | CF 分 ≥ 0.5 | 协同过滤 |
| "越刷越懂你" | 命中意图标签 | 实时意图追踪 |
| "新晋教员" | BASIC 池 | 流量池赛马 |
| "明星教员⭐" | HOT 池 | 流量池赛马 |

## 8. Redis Key 设计一览

| Key 模式 | 类型 | 用途 | TTL |
|---------|------|------|-----|
| `tutor:geo:locations` | GEO | 教员经纬度空间索引 | 永久 |
| `realtime_intent:parent:{id}` | ZSET | 家长实时意图标签排名 | 30 min |
| `tutor_static_tags:{id}` | Hash | 教员静态标签缓存 | 1 hour |
| `traffic_pool:{id}` | String | 教员流量池级别缓存 | 7 days |
| `behavior:tutor:stats:{id}` | String | 教员热度统计缓存 | 10 min |
| `cf:user_similarities:{id}` | String | CF 用户相似度缓存 | 1 hour |
| `intent:actions` | Stream | 意图事件消息队列 | 永久 |

## 9. 优雅降级策略

所有 Redis 操作均包裹 `try-catch`，确保 Redis 不可用时系统仍正常运行：

| 模块 | Redis 不可用时的降级行为 |
|------|----------------------|
| GEO 召回 | 退化为全库查询 |
| 实时意图追踪 | 跳过意图加分，仅使用基础分 |
| 流量池赛马 | 默认所有教员为 BASIC |
| 协同过滤缓存 | 每次重新计算（性能下降但功能正常） |
| 行为统计缓存 | 直接查数据库 |
